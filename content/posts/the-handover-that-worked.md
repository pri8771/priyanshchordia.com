*I moved the conversation. The work was in the files.*

I have an AI session that coordinates my other AI sessions and bots. I call it the quarterback. It runs with a five-hour usage limit, so the quarterback also needs a substitute.

On November 23, at about 4:04 PM Eastern, I was close to that limit and asked it to put the files somewhere and give me a prompt for my other account. It wrote a hand-over folder: a note of 1,052 words, three job scripts, twelve memory notes and a config file.

For moving a conversation.

The note's file time was 4:04:33 PM. Its own heading said about 4:10 PM. Among its instructions was this line:

> trust file times, not the "Updated" line

![the note's section headings typed out, then the line about file times](/blog-media/the-handover-that-worked/handover-note.gif)

The hand-over came with advice on how to disbelieve parts of the hand-over.

The new session started on my other account. Someone else had the job. The someone was another AI session that had never seen the work. I asked it to describe the job in three lines and to:

> check the in-flight items against the disk, not the notes, and rerun what is missing

It found a research report and table already on disk. They had been written at 4:06 PM. That job did not need another go just because I had changed conversations.

Another job had stopped halfway. Its output file contained 191 checked quotes. The project board it was supposed to update contained none of them. The quotes existed. Their arrival was pending.

The new session backed up the board file at 4:23 PM and reran only the last step. At 4:26 PM the board had the goals, and its 120 rows were unchanged.

![the timeline by file time, 4:04 PM to 4:29 PM](/blog-media/the-handover-that-worked/disk-not-notes.gif)

The slightly technical part is that the state lived in files. The note separated standing limits, what I was waiting on, and running jobs with an expected output file for each. The successor could check those outputs against the disk, find the missing step and run just that step, with a backup first. It did not need the old conversation to establish which file existed.

Then it asked to restart the project sessions. I agreed. Seven restarted from their own status and backlog files, the first by 4:29 PM.

One of those sessions drafts this blog. Its status file claimed an update at 4:15 PM. The file's own time was 4:00 PM. The instructions had anticipated the paperwork.

The new session's own log says the board was done at 4:40 PM and the restart came at about 4:45 PM. The files say 4:26 and 4:29. The successor inherited the job and the habit. The times in this post are file times.

An earlier post in this series was about a hand-off note that said nothing was live for customers when four things were. This hand-over worked for the next session, which checked it. Nobody has checked what the note left out.

The restarted blog session then wrote the fact sheet for this post from the hand-over folder and the decisions log. The hand-over now has coverage from a session it restarted.
