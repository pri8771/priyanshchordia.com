## Objective

Create the durable external execution foundation that lets BidetFit inspect trusted Jira work, collect analytics, run bounded research, update code through branches and pull requests, execute tests, verify deployment, and record evidence while the owner's laptop and this ChatGPT conversation are closed.

## Why

The existing GitHub Actions operator provides real unattended deterministic health checks, but it is not an authenticated event-processing or open-ended reasoning runtime. Full operational autonomy needs durable private state, signed events, a queue, leases, secrets, model access, cost controls, observability, action authorization, and recovery.

## Current state

- GitHub Pages and the deterministic six-hour operator run with the laptop off.
- Jira and Notion records exist, but Jira does not trigger execution.
- Search Console, GA4, and affiliate metrics are not collected.
- No separate model API is connected.
- No private event/task state exists.
- No cloud endpoint receives signed Jira, GitHub, Gmail, or internal events.

## Selected architecture

Build a strict-zero-cost GitHub Actions pilot first and prepare a robust Google Cloud event-driven runtime:

- Cloud Run service for authenticated webhooks and orchestration.
- Cloud Run Jobs for bounded analytics, research, testing, and code changes.
- Firestore for tasks, leases, approvals, policies, checkpoints, and receipts.
- Pub/Sub or Cloud Tasks for retries, deduplication, and dead-letter handling.
- Cloud Scheduler for recurring work.
- Secret Manager and least-privilege service accounts.
- GitHub App installed only on the required repository.
- Jira as owner command plane.
- Separately authorized model API for reasoning.

## Requirements

- Create a dedicated non-Primandir project identity.
- Obtain explicit owner authorization before linking billing.
- Configure minimum instances 0, maximum instances 1, concurrency 1, timeouts, quotas, provider spend controls, and kill switches during the pilot.
- Verify signed webhooks and reject unauthorized actor, project, state, timestamp, and payload.
- Store each event and task with an idempotency key.
- Lease a task so only one worker executes it.
- Keep model, code, deployment, email, merchant, and financial authority separate.
- Create code only on a branch and pull request; never bypass tests or branch protection.
- Write immutable execution receipts and sanitized Jira/Notion updates.
- Keep credentials, raw PII, and private analytics out of public systems and logs.
- Document deploy, rollback, recovery, cost, retention, and owner access.

## Out of scope

- Unrestricted shell or repository administration.
- Direct production pushes.
- Unapproved customer email, account, order, return, refund, privacy, legal, or financial actions.
- Using Jira, email, web content, or model output as executable instructions.
- Claiming a ChatGPT subscription provides API compute.

## Acceptance criteria

- [ ] A cloud endpoint or strict-zero fallback runner works while the laptop is off.
- [ ] One trusted Jira event creates exactly one durable task.
- [ ] The worker reads canonical GitHub state and performs a harmless public health check.
- [ ] The worker writes a signed or integrity-bound execution receipt back to Jira.
- [ ] Duplicate and replayed events do not duplicate work.
- [ ] A global kill switch prevents the next execution.
- [ ] Secrets and raw PII are absent from public state and logs.
- [ ] IAM, quotas, cost controls, retries, dead-letter handling, and rollback are tested.
- [ ] Actual provider, model, usage, cost, source SHA, tests, and receipts are recorded.
- [ ] Jira, Notion, GitHub, decisions, risks, diary, and handoff are synchronized.
