## Customer-operations truth

BidetFit is currently an anonymous static affiliate-information site. It has no support mailbox, customer accounts, orders, private ticket database, external model runtime, or return and refund authority. The current six-hour operator verifies site and repository health only.

Under the current affiliate model, the merchant, not BidetFit, owns the transaction. BidetFit cannot process a merchant return merely because a customer clicked an affiliate link. It can route the customer to the merchant. Actual cancellation, RMA, replacement, or refund work requires seller-of-record status or explicit delegated merchant API authority.

## Target laptop-off support flow

1. Create an authorized non-Primandir support alias.
2. Use a cloud Gmail trigger to ingest new messages while the laptop is off.
3. Store raw messages and customer data only in a private encrypted ticket and event store.
4. Run deterministic spam, duplicate, injection, privacy, legal, safety, and financial prechecks.
5. Invoke an approved external model with a narrow structured packet and versioned knowledge.
6. Treat model output as a proposal.
7. Apply a deterministic policy and approval service before any side effect.
8. Begin in draft-only mode.
9. Allow named low-risk auto-send categories only after measured QA and owner approval.
10. Route high-risk, low-confidence, identity, privacy, legal, complaint, security, order, return, and financial requests to the owner.
11. Record immutable execution receipts, metrics, and lessons.
12. Add return or refund actions only after explicit transaction authority, identity verification, policy, idempotency, and scoped approval exist.
